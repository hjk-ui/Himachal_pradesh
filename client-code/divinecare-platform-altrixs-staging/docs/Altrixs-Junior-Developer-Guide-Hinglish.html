Altrixs — Junior Developer Complete Guide (Hinglish)

Kis ke liye: Fresher / Junior developer · Project: Altrixs staff portal · Live site: https://altrixs.com/ (deploy senior/DevOps handle karenge) · Tumhara kaam: local pe feature complete + test, phir PR / code push.

Simple samjho:
Abhi project mein bahut screens sirf dikhti hain (fake/DEMO data). Database se connected nahi. Tumhara goal: ek-ek screen ko asli working banao — UI theek + API + database + workflow. Har din sirf 1 prompt Cursor/AI ko do, kaam karwao, neeche wale Test steps khud chalao. Jab local pe sab theek ho, tab senior ko bolo live altrixs.com pe deploy karne ke liye.

1) Pehle ye cheezein setup kar lo

  1. Laptop pe project folder kholo: divinecare-platform (Altrixs Next.js app).
  2. Terminal: npm install → npm run dev → browser: http://localhost:3000
  3. Database connected hona chahiye (.env mein DATABASE_URL). Agar error aaye to senior se poocho.
  4. Login try karo (password sabka: Altrixs@123):
    • admin@altrixs.local
    • clinician@altrixs.local
    • frontdesk@altrixs.local
    • billing@altrixs.local
    • hr@altrixs.local
    • director@altrixs.local
  5. Har din ke baad ye command chalao: npx tsc --noEmit — error nahi aana chahiye.

2) Abhi kya LIVE hai / kya sirf UI hai

ScreenStatusMatlab
Login, Dashboard, Clients list, Appointments, HR staff invite, Settings, Platform adminLIVEDatabase se connected — pehle mat todo
Client detailHalf doneKuch kaam karta hai, Notes waghera incomplete
Waitlist, Intake, Messages, Alerts, To-Do, Telehealth, EHR notes/plans, Billing, Credentials…UI ONLYFake data — ye complete karna hai
Fresher tip: “UI ONLY” ka matlab page sundar dikhta hai, lekin refresh / dusra laptop pe data gayab / fake rehta hai. “LIVE” ka matlab create karo → refresh → data wahi hai (database mein save).

3) Har din ka flow (yaad rakhna)

  1. Prompt copy karo (neeche Day box se) → Cursor chat mein paste.
  2. AI/code complete hone do.
  3. Test checklist khud chalao (tick karo).
  4. Agar fail → AI ko bolo: “Ye test fail hua: …” aur fix karwao.
  5. Pass ho → short note likho (kya banaya) → next day.
  6. Deploy tum mat karna jab tak senior na bole. Local pass = ready for live.

4) Daily prompts + testing (1 by 1)

DAY 1 — Client Detail page complete karo

Screen: Clients → kisi client pe click (/dashboard/clients/[id])

Kyun zaroori: Baaki workflow isi patient record pe depend karta hai.

Cursor ko ye prompt do:

Day 1 — Client Detail ko fully working banao. Route: /dashboard/clients/[id] Problem: Client load/avatar already API se aata hai, lekin Notes tab local/fake hai. Check-ins aur appointments tab incomplete ho sakte hain. Kaam: 1) Clinic UI polish (clean cards). 2) Notes database mein save ho (Prisma model + API). Refresh ke baad note rahe. 3) Appointments tab isi client ki real appointments dikhaye. 4) Check-ins: mood/stress add ho aur list/chart update ho. 5) Insurance fields edit + save (existing client PATCH API use karo). 6) roleAccess respect karo. Done tab jab: note create → hard refresh → note wahi; insurance save → reload same; tsc clean.
Tum kya test karoge (local):
  1. clinician@altrixs.local se login.
  2. Clients → ek client kholo.
  3. Notes tab: naya note likho → Save → page refresh (Cmd+R) → note dikhna chahiye.
  4. Check-Ins: mood 3, stress 8 add karo → list mein aaye.
  5. Insurance: payer badlo → Save → refresh → wahi payer.
  6. Appointments tab: agar us client ki appointment hai to dikhe (pehle Appointments se bana ke check kar sakte ho).
  7. Terminal: npx tsc --noEmit OK.
DAY 2 — Waitlist Manager LIVE banao

Screen: /dashboard/clients/waitlist · Role: Front Desk

Day 2 — Waitlist Manager ko DEMO hata ke real backend pe lao. Route: /dashboard/clients/waitlist Kaam: 1) Prisma WaitlistEntry model (name, phone, specialty, urgency, status, insurance, notes, clinicianId, org). 2) APIs: list/create/update/match/close. 3) Match clinician → staff list se assign. 4) Convert to intake/client → Clients list mein naya client bane. 5) Page se DEMO array hatao; UI (table + detail) rakho. 6) Front Desk access; Billing ko waitlist na dikhe. Done: add → refresh → entry rahe; match + convert client banaye.
Test:
  1. frontdesk@... login → Waitlist.
  2. “Add to Waitlist” → form bharo → list mein aaye.
  3. Hard refresh → entry gayab NA ho.
  4. Match to Clinician → status Matched.
  5. Convert / intake → Clients page pe naya patient dikhe.
  6. billing@... login → Waitlist nav mein nahi hona chahiye.
DAY 3 — Digital Intake LIVE

Screen: /dashboard/clients/intake

Day 3 — Digital Intake packets real banao. Route: /dashboard/clients/intake Kaam: 1) IntakeInvite model (email/token/status pending|completed|expired + form data). 2) Create/list/complete APIs. 3) Complete hone pe Client create/update (demographics + insurance). 4) Waitlist se “Convert to Intake” isse jude. 5) DEMO hatao. Done: intake complete → Clients mein data dikhe.
Test:
  1. Front Desk → Digital Intake → naya invite/packet banao.
  2. Complete mark karo (demo form fill) → Clients pe patient dikhe/update ho.
  3. Refresh ke baad status sahi (completed).
  4. Waitlist convert se bhi pending intake bane.
DAY 4 — Consent Forms LIVE

DAY 5 — Messages LIVE (model pehle se hai)

DAY 6 — Risk Alerts LIVE

Screen: /dashboard/alerts

Day 6 — Risk Alerts ko RiskAlert model se connect karo. Kaam: 1) /api/risk-alerts GET + review PATCH. 2) alertsApi stub implement. 3) Page se DEMO_ALERTS hatao. 4) Workflow: Check-in pe mood <=3 ya stress >=8 → auto alert create. 5) Review → reviewed=true. Done: low mood check-in → Alerts pe dikhe; review ke baad unreviewed se hate.

  5. Front Desk ko Alerts nav na dikhe.
DAY 7 — Progress Notes (EHR) LIVE

DAY 9 — My To-Do real queue

6) Poora clinic flow — final exam (local)

Jab Day 1–15 ho jaaye, ye full story ek baar chalao (jaise asli clinic):
  1. Front Desk: Waitlist add → Match → Intake complete → Client banega.
  2. Front Desk: Consent sign + Appointment book (virtual bhi).
  3. Clinician: Telehealth/start → Complete → Progress note draft → Sign.
  4. Clinician: Low mood check-in → Alert aaye → Review.
  5. To-Do: Unsigned note task clear ho sign ke baad.
  6. Billing: Claim draft → Submit.
  7. HR: Credential + Supervision log.
  8. Admin: Staff invite / locations pehle se chalna chahiye.
Agar ye 8 steps pass → project “working clinic MVP” maan sakte ho. Phir senior se kaho https://altrixs.com/ pe deploy kare.

7) Deploy ke baare mein (tumhara nahi, senior ka)

  • Tum: local test pass + PR / branch push.
  • Senior/DevOps: production deploy to https://altrixs.com/.
  • Deploy ke baad bhi wahi Test checklist live pe smoke test karo (login + 1 create/refresh).
  • Live pe kabhi bhi seed passwords production users ke liye mat use karna — sirf local.

8) Agar stuck ho jao

  • Error screenshot + “Day number + kaunsa test fail” AI ko do.
  • Pehle confirm karo: sahi role se login ho? npm run dev chal raha? DB up?
  • Ek din mein 2 screens mat mix karo — fresher galti yahi hoti hai.
  • DEMO array page pe reh gaya kya? Search karo DEMO us file mein — hona nahi chahiye after that day.
