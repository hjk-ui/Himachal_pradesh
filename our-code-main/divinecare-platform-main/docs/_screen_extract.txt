4. Recommended delivery order (why)
1. Days 1–2: Wire Client Detail gaps + Waitlist (Front Desk intake funnel)
2. Days 3–4: Digital Intake + Consents (eligibility for first appointment)
3. Days 5–6: Messages + Risk Alerts (models exist — fastest wins)
4. Days 7–8: Clinical Notes + Treatment Plans (clinician core EHR)
5. Days 9–10: Tasks (derived from unsigned notes / expiring PA) + Telehealth link to appointments
6. Days 11–13: Eligibility, Prior Auths, Billing claims spine
7. Days 14–15: HR credentialing + supervision
8. Days 16+: AI/analytics shells — only after core workflow is green
5. Global rules for every Day prompt
Keep NextAuth + roleAccess.ts enforcement. Add server-side canAccessPath in proxy.ts when touching authz.
Remove DEMO_* arrays from the target page; load from API. Empty states OK.
Add Prisma models + migration via prisma db push (or migrate) scoped to that domain.
Match Amanah-style clinic UI already used on Waitlist/To-Do (soft cards, pills, navy/purple).
Wire workflow links: e.g. Waitlist “Convert to Intake” → create Client; Appointment COMPLETED → create unsigned Note task.
Do not invent third-party integrations (Availity, Zoom) — stub provider interface with local persistence.
After code: npx tsc --noEmit must pass.

DAY 1 — Client detail completionPARTIAL → LIVE
Route:/dashboard/clients/[id] · Roles: Clinician, Front Desk, Admin
Day 1 — Finish Client Detail so every tab is backend-backed.
Context: `/dashboard/clients/[id]` already loads client via `/api/clients/[id]` and avatar upload works. Notes tab 
is local-only. Appointments/check-ins may be incomplete.
Do:
1) UI polish to match clinic design system (PageHeader style, soft cards).
2) Persist clinical notes on the client (Prisma: add ClientNote model OR reuse Message with type — prefer ClientNote 
with authorId, body, createdAt).
3) Appointments tab: list this client's appointments from existing Appointment model via API.
4) Check-ins tab: read CheckIn rows for client; allow staff to add a check-in (mood/stress/note).
5) Insurance tab: edit insurance fields already on Client; PATCH `/api/clients/[id]`.
6) Enforce roleAccess; Clinician only sees assigned clients if already gated.
Acceptance: create note → refresh → still there. Add check-in → chart updates. Edit insurance → persists.
How to test after Day 1
1. Login as clinician@altrixs.local → Clients → open a client.
2. Notes: add note → hard refresh → note remains with author/timestamp.
3. Check-Ins: add mood/stress → appears in list/chart.
4. Insurance: change payer → save → reload → same value.
5. Appointments tab shows real rows if that client has appointments (create one from Appointments page first).
6. npx tsc --noEmit clean.
